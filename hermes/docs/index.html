Overview

Hermes is a task management system built on Notion that automatically prioritizes and routes work using a cheapest-first strategy.

Smart Prioritization

Automatically processes the lowest-effort tasks first, ensuring quick wins and maintaining momentum.

Automated Routing

Tasks flow through specialized pipelines (Automation, Research, Report, Content) without manual intervention.

Centralized Tracking

Everything lives in Notion — no new tools, no context switching, no data silos.

Three Tiers of Operation

Hermes grows with your needs through three operational tiers:

Tier 1: Manual

Best for: Pilots & testing

  • 1-hour setup
  • Button-click dispatch
  • Zero code
  • Requires a human to click

Tier 2: Scheduled

Best for: Production use

  • Polls every 5 minutes
  • Fully automated
  • dispatcher_tier2.py
  • Slight dispatch delay

Tier 3: Real-time

Best for: Larger scale

  • Webhook + polling fallback
  • Parallel task cap
  • dispatcher_tier3.py
  • Needs hosting

API Reference

Running the dispatchers

pip install -r requirements.txt cp .env.example .env # fill in NOTION_TOKEN and DATABASE_ID python3 dispatcher_tier2.py # Tier 2, polling every 5 min python3 dispatcher_tier3.py # Tier 3, webhook + 30s polling fallback

Environment Variables

NOTION_TOKEN Notion integration token DATABASE_ID Hermes database ID WEBHOOK_PORT Port for the Tier 3 webhook server (default 5000) MAX_PARALLEL_TASKS Max concurrent Running tasks for Tier 3 (default 3) WEBHOOK_SECRET Shared secret for a generic caller on POST /webhook NOTION_WEBHOOK_SECRET Notion's verification_token, used to check the X-Notion-Signature HMAC on real Notion webhook events (takes precedence over WEBHOOK_SECRET if both are set)

Tier 3 Endpoints

POST /webhook Trigger an immediate dispatch pass. Either: - generic caller: header X-Webhook-Secret: <WEBHOOK_SECRET> - Notion webhook: accepts the one-time verification_token handshake, then verifies X-Notion-Signature on events GET /status Health check: running task count, max parallel, timestamp

Troubleshooting

Button doesn't work

Check that the filter is Status = Pending and the sort is Cost ascending.

Automation not triggering

Verify both conditions: Status = Running AND Pipeline = Automation.

Cost formula shows an error

Make sure Pipeline is a Select property with the exact option names used in the formula.

Script can't connect

Check NOTION_TOKEN and DATABASE_ID in .env, and confirm the database is shared with the integration.

Tasks stuck in Running

Non-Automation pipelines need to be completed manually or via an additional automation.
